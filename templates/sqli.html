Análisis Técnico de Seguridad

{% if tipo == 'vulnerable' %}

¿Por qué es vulnerable este modo?

El backend utiliza formato directo de cadenas (f"SELECT ... WHERE usuario = '{query_param}'"). Esto permite que cualquier comilla simple cierre el valor original y altere la gramática SQL de la consulta.

Solución recomendada por OWASP: Utilizar consultas parametrizadas donde el motor de base de datos trata el valor de entrada estrictamente como dato literal y nunca como código ejecutable.

{% else %}

¿Por qué es seguro este modo?

El backend utiliza marcadores de posición (? en SQLite) y envía los parámetros de forma independiente al motor de base de datos. Aun si la entrada contiene caracteres como comillas o comandos SQL, el motor no los interpreta como instrucciones.
